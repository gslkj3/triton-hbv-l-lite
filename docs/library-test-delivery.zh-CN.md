# FlagGems / FlagGems-vLLM 测试交付要求

状态：接入中，尚不是可执行完成版；不能用普通pytest通过代替L-lite候选被测试。

## 测试入口

使用两个算子库自身的真实Python测试与输入，不以手写TTIR替代。测试适配器应
在实际JIT调用处绑定源码、实参、constexpr和grid，再进入core.lite_entry的
公共候选编译及原生autotune。不得复制历史工程的专用family编译器。

必须记录每个测试是否真正调用候选编译器。未进入、无合法候选、物化失败、
资源超限、数值错误、超时及正常完成分别报告；不能把原生执行成功记成L-lite成功。
嵌套原生autotune、libentry缓存、warmup和CUDA graph捕获的调用边界需明确处理，
不能在计时或图捕获内部递归启动另一轮autotune。

## 用户可配置项

外部库路径/版本、Python环境、GPU编号、pytest节点或节点清单、Bridge与route
factor候选集、输出目录、每个节点超时（默认900秒）。不得固定算子名或形状
作为候选资格；测试清单只是执行范围，不参与Pass判断。

## 输出

逐节点JSON及Markdown汇总：测试状态、是否进入L-lite、原生与候选耗时、最佳
route/factor、加速比、总autotune墙钟开销（含候选编译）、失败类型。保留完整
分母和超时，不仅列成功样例。正确性与收益结论分开；记录设备、源码、编译器
身份及运行环境。原始结果不由重跑覆盖。

## 交付顺序

1. 独立L-lite分支重建新版编译器并通过Python端到端测试。
2. 实现真实库调用适配与逐节点限时执行，不自动下载或改写两个外部库。
3. 两个库分别跑小范围完整冒烟，确认候选编译实际发生且结果可归因。
4. 再交付批量命令及报告；用户确认GPU编号前不启动GPU批量任务。
